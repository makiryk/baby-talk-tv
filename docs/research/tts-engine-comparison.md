## 1. 背景と課題

### 1.1 現状の実装と課題
現在、`baby-talk-tv` の音声合成部（`TtsManager.kt`）は、Android OS 組み込みの `android.speech.tts.TextToSpeech` API を使用し、ピッチ（1.3倍）と話速（0.85倍）を設定して発話させています。
しかし、Android TV に搭載されている標準の音声エンジン（Google 音声サービス等）には以下の課題があります：
- **機械的・平板な読み上げ**: イントネーションの抑揚が乏しく、ロボット声になりがち。
- **マザーリーズ（対乳児発話）の不足**: 赤ちゃんが安心・注目する「高音（+2〜+4半音）・豊かな抑揚・包み込むような温かみ」を表現しきれない。
- **既存実装の潜在バグ**: `TtsManager.kt` 内の `playAudioFile` において、`prepare()`（同期呼び出し）の後に `setOnPreparedListener` を設定しているためリスナーが発火せず、事前合成ファイル再生時に発話開始コールバックが呼ばれずタイムアウトする問題が存在。

### 1.2 検討の目的と先行設計（`audio.md`）との関係
先行設計書 `audio.md` では「Google Cloud TTS (Neural2) をメイン、組み込みTTSをフォールバック、バッチ時に事前合成してローカル保存する」という基本方針が策定されていました。
本検討書は、ユーザーからの「音声ライブラリをもっと自然な読み上げを行えるアプリへの変更を検討して」という要望を受け、**外部TTSアプリ連携、オンデバイスAIライブラリ、クラウドAPI、アセット事前同梱**の各アプローチを技術的・運用的に再評価し、具体的な実装計画へ落とし込むためのものです。

## 2. 検討対象のアプローチ

### アプローチ1-A: 外部オンデバイスTTSアプリ連携（ボイボTTS等）
Android OS の「テキスト読み上げの設定」でサードパーティ製TTSエンジン（ボイボTTSなど）を優先エンジンに設定するか、アプリ側から特定パッケージ（`TextToSpeechService`）を明示バインドする方式。

- **候補アプリ**: **ボイボTTS** (VOICEVOX音声エンジン内蔵アプリ: 四国めたん、ずんだもん、春日部つむぎ等)
- **メリット**:
  - キャラクター音声特有の表情豊かで親しみやすい声質。
  - 完全オンデバイス動作（外部通信なし）。
- **課題・デメリット**:
  - **Android TV Playストア未対応**: スマホ用APKのサイドロードが必須。
  - **TVリモコンでの設定困難**: タッチUI前提のためD-Pad操作が非常に困難。
  - **プロセス安定性**: TVのメモリ制約によりバックグラウンドで強制終了（LMK）されるリスク。
  - **ライセンス要件**: VOICEVOXキャラクターの利用規約（クレジット表記要件など）の遵守が必要。

---

### アプローチ1-B: 外部クラウドTTSブリッジアプリ連携（Tetsy等）
OpenAI TTS や ElevenLabs を Android のシステムTTSとして中継するアプリを利用する方式。

- **メリット**: 人間そのものの極めて自然な発話。
- **課題・デメリット**:
  - サイドロード必須、リモコン設定困難。
  - クラウド通信を挟むため、発話レスポンスに1〜3秒以上の遅延が発生し、会話テンポが破綻する。
  - プライバシー保護規程（外部アプリ経由での通信）への懸念。

---

### アプローチ2: アプリ組み込みオンデバイスAI音声ライブラリ（`sherpa-onnx` + Kokoro-82M / VITS）
アプリ内に `sherpa-onnx-android` を組み込み、オンデバイスでニューラル音声合成を行う方式。

- **採用モデル候補**: **Kokoro-82M (Multilingual 日本語)** または **Piper / VITS**
- **メリット**:
  - 外部アプリ不要（アプリ単体で完結）。
  - 完全オフライン・プライバシー100%保護。
  - スタジオ品質の自然な日本語女性声（`jf_alpha` 等）。
- **課題・デメリット**:
  - **端末負荷とリアルタイム遅延**: Android TV のエントリーSoC（Quad-core Cortex-A53等）では、Kokoro-82M の推論速度（RTF: Real Time Factor）が1.0を下回る（発話時間以上の生成時間がかかる）可能性が高く、**対話時のリアルタイム生成には不適**。
  - **サイズ増加**: モデルファイル（int8量子化でも数十MB）によりAPKサイズが増加。
  - **ピッチ制御の制約**: Kokoro は話速（speed）の指定は容易だが、マザーリーズ特有の「ピッチ+3半音」を動的に変更するには波形後処理が必要。
- **位置づけ**: 対話時の即時生成ではなく、**「夜間・アイドル時のオンデバイス事前合成エンジン」**としての活用が現実的。

---

### アプローチ3: クラウド高品質AI音声APIによる事前バッチ生成（Google Cloud TTS `ja-JP-Neural2-B`）
日次バッチ同期時（ClaudeバッチAPI実行時）に、Google Cloud TTS API でフレーズ音声を端末ローカルストレージ（WAV/MP3）に一括生成・保存し、対話時は `MediaPlayer` で即時再生する方式。

- **推奨音声**: **`ja-JP-Neural2-B` (女性)**
  - SSML に完全対応（`<prosody pitch="+3st" rate="88%">` が確実に動作）。
  - （注: Journey 音声は日本語未対応またはピッチ指定不可のため不採用。OpenAI TTS も SSML によるピッチ微調整が不可）。
- **メリット**:
  - **極上のマザーリーズ品質**: 高ピッチ・ゆったりテンポ・豊かな抑揚が完全にコントロール可能。
  - **端末負荷ゼロ ＆ 低遅延（数十ms以内）**: 端末は保存済みファイルを再生するだけ。
  - **コスト効率**: Google Cloud TTS の Neural2 音声は月間100万文字まで無料枠（本アプリの日次バッチは数十〜数百文字程度のため完全無料枠内で収まる）。
- **課題・デメリット**:
  - Google Cloud APIキー（またはサービスアカウント）の設定が必要。
  - TVリモコンでのキー入力対策が必要（ローカルWeb設定画面やQRコード連携）。

---

### アプローチ4: 初期シードフレーズ（約50件）の高品質音声「アセット同梱」（★即効性No.1）
あらかじめ開発・ビルド時に Google Cloud TTS (`ja-JP-Neural2-B`) を用いて、アプリ内蔵の初期フレーズ約50件（`preloaded_phrases.json`）の音声ファイル（MP3）を生成し、アプリの `src/main/assets/audio/` に同梱する方式。

- **メリット**:
  - **APIキー不要・設定不要**: ユーザーがインストールした瞬間から、最高品質のマザーリーズ音声が再生される。
  - **完全オフライン動作**: ネット未接続でも最初から高品質。
  - **サイズ影響極小**: 50フレーズ分の短尺MP3（各1〜2秒）は合計で約2〜3MB程度に収まる。
  - **声の一貫性**: 最初から最後まで同一の `Neural2-B` ボイスで話しかけられるため、赤ちゃんに安心感を与えられる。

## 4. 推奨アーキテクチャ ＆ 具体的な移行ロードマップ

赤ちゃんへの「**声の一貫性（Voice Consistency）**」と「**設定不要で即使えるUX**」を両立するため、以下のステップでの移行を推奨します。

### 全体アーキテクチャ構成
```
[発話要求 (Phrase)]
       │
       ├─ ① [最優先・常時] ローカルに事前合成オーディオファイル (.mp3) があるか？
       │       ├─ A. アプリ内蔵アセット (`assets/audio/*.mp3`)
       │       └─ B. バッチ同期キャッシュ (`files/audio_cache/*.mp3`)
       │              └─ YES ──> MediaPlayer で即時再生 (準備済み再利用、数十ms以内)
       │
       └─ ② [フォールバック] 音声ファイル未存在時
              └─ Android OS 組み込み TextToSpeech
                     ├─ Google 音声サービスの高品質ボイス (setVoice) を優先探索
                     └─ 不在時は標準ボイス (ピッチ1.2f, 速度0.88f) で発話
```

### 段階的移行ロードマップ

#### 【ステップ1】（即時実施・バグ改修 ＆ アセット同梱）
1. **`TtsManager.kt` の再生バグ修正**:
   - `prepare()` の後にリスナーを設定していた箇所を、`setOnPreparedListener` を設定した上で `prepareAsync()` を呼ぶ非同期安全設計に修正。
   - `AudioFocus`（`AUDIOFOCUS_GAIN_TRANSIENT_MAY_DUCK` または `AUDIOFOCUS_GAIN_TRANSIENT`）の適切な取得と解放を実装。
   - 再生失敗時のTTSフォールバックを実装。
2. **初期シードフレーズ（50件）の高品質音声MP3をアセット同梱**:
   - Google Cloud TTS (`ja-JP-Neural2-B`, `pitch="+3st"`, `rate="88%"`) で生成した約50個のMP3ファイルを `assets/audio/` に配置。
   - `PhraseRepository` にて、初期シード読み込み時に `audioPath` としてアセットパスを紐付け。
   - **これにより、APIキー設定なし・外部アプリなしで、インストール直後から極上マザーリーズが即時稼働します。**

#### 【ステップ2】（日次バッチ同期でのクラウドTTS事前合成）
1. **`ClaudeBatchApiClient` / `BatchPhraseSyncWorker` との連携**:
   - Claude バッチから新フレーズを取得した際、Google Cloud TTS API を呼び出して MP3 をダウンロード。
   - 安全なファイル保存（一時ファイル `.tmp` に書き込み後、Atomic rename で破損防止）。
   - キャッシュ容量制限（例: 最大200件 / 50MB）と LRU 削除ポリシーの実装。
2. **APIキー設定のUX改善**:
   - TVリモコンでの入力を避けるため、簡易ローカルWebサーバーまたはQRコードによるスマホ連携設定画面を提供。

#### 【ステップ3】（将来拡張: オンデバイスAI `sherpa-onnx` の夜間バッチ検証）
- ネット環境のない家庭向けに、夜間充電時・アイドル時に `sherpa-onnx` を用いてローカルで翌日分のフレーズ音声を事前合成する実験的スパイクを実施。

## 5. ライセンス・利用規約およびプライバシー

1. **Google Cloud Text-to-Speech**:
   - 生成した音声ファイルをエンドユーザー端末のローカルキャッシュとして保存・再生することは利用規約上許可されています。
   - フレーズテキストはClaudeが生成した一般的な対話文のみであり、赤ちゃんの個人情報（名前等）は一切含めないため、プライバシー規程を100%遵守します。
2. **VOICEVOX**:
   - 将来的に外部連携する場合は、各キャラクターのクレジット表記（例:「VOICEVOX:四国めたん」）を画面またはヘルプに明記する必要があります。
3. **Kokoro / sherpa-onnx**:
   - Apache 2.0 ライセンス。商用・非商用を問わず無償利用可能。
